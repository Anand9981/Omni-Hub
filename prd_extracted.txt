1. EXECUTIVE OVERVIEW & PRODUCT VISION
1.1 Problem Statement
Modern businesses interact with customers across diverse communication channels including WhatsApp, Instagram, Telegram, Discord, LinkedIn, and Website Live Chat Widgets. Managing these channels separately leads to critical operational bottlenecks:
• High Response Delays: Delayed responses to routine customer inquiries lead to missed business opportunities.
• Repetitive Manual Work: Support representatives spend excessive time answering recurring questions regarding pricing, setup instructions, and catalogs.
• Risk of AI Misinformation: Fully autonomous AI bots can generate inaccurate pricing or unverified offers, negatively impacting brand reputation.
• Fragmented Customer Data & Invisible Metrics: Customer contacts are scattered without central CRM synchronization, and business owners lack visibility into channel traffic, message counts, and agent response performance across platforms.
• Zero Cross-Channel Analytics: Business owners cannot answer basic questions such as "How many messages arrived on WhatsApp today versus Instagram?" — leading to blind operational decisions.
1.2 Product Vision
OmniHub consolidates customer interactions from six primary messaging channels into a single central dashboard. The system integrates:
1. Automated post-service interactive button navigation.
2. Instant delivery of rich media assets such as PDF brochures, catalogs, and images.
3. Gemini AI auto-responses for open queries in English, Hindi, and Hinglish.
4. Client Approval Mode (Human-in-the-Loop) allowing business owners to review, edit, and approve AI replies before delivery.
5. An Auto-Pilot Switch enabling seamless transition between automated responses and direct human agent takeover.
6. Real-time Graphical Analytics and Daily Channel Traffic Reports providing visual insights into inbound messages versus outbound replies across all connected applications.
7. Multi-Channel Daily Traffic Dashboard — app-wise inbound and outbound counters with four interactive graphs (Bar, Donut, Line, Stacked).

5. AUTHENTICATION & USER ONBOARDING
This module handles dashboard login, OTP verification, and user account management.
5.1 Admin Registration & Login
• Email and Password registration — Admin creates their own account
• Email verification — A verification link is sent to the registered email after signup
• Password policy — Minimum eight characters, one uppercase letter, one number, one special character
• Login with Email and Password — A JWT token is generated
• Remember Me option — Session maintained for thirty days
• Forgot Password — A reset link is sent to the registered email
• Password reset token — Expires within fifteen minutes
5.2 OTP Verification (Two-Factor Authentication)
• OTP after login — A six-digit OTP is sent to the registered email
• OTP expiry — Five minutes
• Resend OTP — Thirty second cooldown, maximum three attempts
• Maximum attempts — Account locked for fifteen minutes after five incorrect OTP entries
• Device binding — Device is remembered after successful OTP verification
• Backup codes — Ten emergency codes are generated
5.3 Session Management
• JWT Access Token — Fifteen minute validity
• Refresh Token — Seven day validity, rotated on every refresh
• Concurrent session limit — Maximum three devices
• Session timeout — Automatic logout after thirty minutes of inactivity
• Login audit log — IP address, device, and timestamp saved for every login
• Suspicious login alert — Email alert on login from a new device or location
5.4 User Roles
• Super Admin — Full system access
• Admin — Dashboard access, can approve
• Agent — Handles conversations only
• Viewer — Read-only access, cannot make changes
6. UNIVERSAL INGESTION & DATA NORMALIZATION ENGINE
This engine receives incoming messages from every platform, validates their origin, and converts them into a common format.
6.1 Platform Webhook Receivers
Each platform has its own webhook endpoint:
Telegram Bot API Receiver
• Endpoint: /api/webhooks/telegram
• Receives text messages, button clicks, and voice clips
• Verified using Bot Token
• Free and the easiest setup
Discord Gateway Receiver
• Endpoint: /api/webhooks/discord
• Captures direct messages and channel messages
• Verified using Bot Token
• Free and unlimited
Instagram Graph API Receiver
• Endpoint: /api/webhooks/instagram
• Receives DMs, story mentions, and media replies
• Verified using Meta Webhook signature
WhatsApp Cloud API Receiver
• Endpoint: /api/webhooks/whatsapp
• Receives incoming messages, button clicks, and media receipts
• Verified using Meta Cloud API
LinkedIn Messaging Receiver
• Endpoint: /api/webhooks/linkedin
• Captures organization page messages
• Skipped during trial, added later
Website Live Chat Socket Engine
• Real-time bi-directional connection
• Connected to the website widget through Socket.io
• One hundred percent free, self-built
6.2 Webhook Security & Verification
• Signature Validation — X-Hub-Signature-256 verified using HMAC-SHA256 for Meta platforms (WhatsApp and Instagram)
• Token Verification — Authorization token checked for Telegram and Discord
• Replay Attack Prevention — Duplicate messages rejected using timestamp and unique ID
• IP Whitelisting — Webhooks accepted only from trusted IP addresses
• Rate Limiting — Maximum one thousand requests per minute per platform
6.3 Data Normalizer (Universal Schema)
Every platform sends messages in a different format. The normalizer converts them into a common format:
• message_id — System-wide unique identifier
• platform — Source channel (telegram, discord, and so on)
• external_chat_id — Platform's own chat identifier
• sender_name — User's name
• sender_contact — Phone or email, if available
• message_type — TEXT, BUTTON_CLICK, MEDIA, or VOICE
• text_content — Message text
• media_url — Link to media, if present
• timestamp — ISO-8601 UTC format
6.4 Message Deduplication
• Unique message_id — Every message's unique ID is saved in the database
• Duplicate detection — The same message arriving again is ignored
• Idempotency — Webhook retries do not cause double counting

8. MULTI-LINGUAL AI ENGINE & PROMPT ENGINEERING
This module generates AI responses to open-ended queries.
8.1 Multi-Lingual Capabilities
• English — Complete comprehension and fluent generation
• Hindi (Devanagari) — Responses in formal Hindi script
• Hinglish (Roman Script) — For example, "Account setup kaise karein?" receives "Account setup karne ke liye inn steps ko follow karein..."
• Language Matcher Guarantee — The AI always replies in the user's own language
8.2 Knowledge Base & Context Rules
• Business Context Injection — Business name, services, working hours, pricing, and asset links are supplied to the AI
• Anti-Hallucination Guardrails
• The AI cannot invent fake prices, offers, or promises
• If a query cannot be answered: "Main aapki query note kar raha hoon. Hamari team jald hi aapase contact karegi."
• Response Length Limit — Maximum three sentences
• Tone Control — Professional, friendly, and helpful
8.3 AI Response Generation Flow
1. The user's message is received
2. The language is detected
3. The message is sent to the AI with business context
4. The AI generates a reply
5. The reply is trimmed to three sentences
6. The client approval mode is checked
7. The message is sent once approved
8.4 AI Fallback Handling
• Gemini API Down — "Our AI service is busy. A support agent will assist you shortly."
• Timeout — Same fallback message
• Rate Limit — Queued for retry
• Invalid Response — Forwarded to a human agent

23.3 Exception & Edge Case Handling Matrix
Meta Webhook Timeout (over 15 seconds)
• Risk: High
• Impact: Meta marks the endpoint unresponsive
• Mitigation: Immediate HTTP 200 OK and asynchronous processing
Gemini AI API Downtime
• Risk: Medium
• Impact: AI auto-reply fails
• Mitigation: Send a fallback message
Expired OAuth Access Token
• Risk: High
• Impact: Outbound replies fail with HTTP 401
• Mitigation: NEEDS_REAUTH flag and dashboard alert
Unsupported Media Format
• Risk: Low
• Impact: Render error
• Mitigation: Save the media URL and show a download link
Duplicate Webhook Delivery
• Risk: Medium
• Impact: Double counting
• Mitigation: Unique constraint on message_id
Database Connection Exhausted
• Risk: High
• Impact: All requests fail
• Mitigation: PgBouncer and retry logic
User Sends Abusive Content
• Risk: Medium
• Impact: Brand reputation
• Mitigation: Content filter and auto-flag
AI Generates Wrong Price
• Risk: High
• Impact: Business loss
• Mitigation: Anti-hallucination guardrails and approval mode
